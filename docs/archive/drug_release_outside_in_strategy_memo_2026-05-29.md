# Drug Release Outside-In Strategy Memo

Date: `2026-05-29`

Purpose:

```text
State the current outside-in strategy in the shortest useful form:
1. what the external field is optimizing for,
2. what open slot we should occupy,
3. where our moat actually comes from,
4. what not to waste energy on.
```

## 1. The field is split, not unified

The external field is not converging on one dominant release-ML stack.

It is splitting across three pressures:

1. `benchmark pressure`
2. `workflow / platform pressure`
3. `infrastructure pressure`

Reference figure:

- [competitor_landscape.png](D:/release-foundation/outputs/92_release_strategy_figures/competitor_landscape/competitor_landscape.png)

That matters because each pressure rewards a different kind of paper.

## 2. The open slot is not "best PLGA regressor"

The open slot is:

```text
shared release-intelligence stack
= shared schema
+ shared partially observed benchmark
+ shared posterior-family object
+ mechanism-specific decoders
+ shared timing / shape / uncertainty reporting
```

Reference:

- [unified_release_intelligence_contract_2026-05-29.md](D:/release-foundation/docs/unified_release_intelligence_contract_2026-05-29.md)

This is the bold claim that is still legal now.

## 3. Our current moat

The moat is not one miracle model.

The moat is the combination of:

1. audited PLGA forecasting evidence
2. a first non-PLGA liposome bridge
3. a shared posterior-family object
4. a calibrated-family panel across `PLGA + liposome`
5. prospective lock discipline before chitosan reveal

## 4. Where to fight

Fight direct rivals on the forecasting core:

- `NC / Bannigan`
- explainable LAI few-shot systems
- newer PLGA supervised predictors

Reason:

- these are the works most likely to become reviewer defaults

## 5. Where to borrow

Borrow from:

- liposome workflow papers
- Scientific Data / AI-ready data infrastructure
- computational pharmaceutics and hybrid modeling language

Reason:

- these make the unified stack more real without collapsing it back into
  simple direct regression

## 6. Where to defend

Defend against:

- FormulationLAI
- FormulationAI
- active-learning / optimization platforms

Reason:

- if we stay only at "better prediction," they can still look more useful

That is why the long game should move toward:

`release intelligence -> release decision-support`

## 7. What not to waste time on

Do **not** spend the next phase trying to win by:

1. only adding one more PLGA benchmark cell
2. pretending a black-box universal model already exists
3. rebranding direct regression as unification

Those moves would make the project smaller, not larger.

## 8. Best next strategic move

If the goal is to make the project genuinely harder to dismiss, the strongest
next technical move is still:

> route-consistent uncertainty-aware duration / shape

Because that is the main missing layer between current forecasting evidence
and a true release decision-support stack.

## Bottom line

The outside-in strategy is:

> fight benchmark rivals on forecasting,
> borrow infrastructure and mechanism discipline,
> defend against platform systems by occupying the unified release-intelligence
> slot before they do.
